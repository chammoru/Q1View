## Current decisions

- Reuse the existing menu bar, not an additional toolbar. Current wide order: File, resolution, pixel format, FPS, Browse, Options, Compare, Help, actual read-only magnification. Browse is immediately left of Options. Remove the added Fit/fixed 100% controls and their Options commands. File > Open and Ctrl+O provide file opening without a duplicate button. View and More are removed; Image Scaling and Theme remain under Options. Comparator keeps its existing layout.
- Use actual font/DPI/text-scale measurements, retaining text instead of shrinking it. Narrow windows wrap visible commands as before; no original input menu is hidden. Decoded sources retain disabled RAW interpretation. Viewer keeps its trailing right-aligned group together when that group fits one row.
- Reuse the root HMENU, popup HMENUs, existing command IDs, native menu tracking and execution guards. Resource order, native button order and visual order agree. Existing Alt access keys and shortcuts are preserved except the explicitly removed View and More roots.
- Browse shows its active state through the shared selection palette, never a disabled dashed outline. Mouse-wheel zoom and internal automatic fitting retain their existing transforms and synchronization; the live magnification is information, not an executable command.
- Move dimensions, active input/conversion format, zoom, Fit/Manual, sampling mode and multi-frame position into a native read-only Static status line with a 24-DIP minimum height. BGR888 on a decoded photo describes the active buffer interpretation, not JPEG storage. Ready/Loading does not fabricate loaded dimensions or zoom. Frame numbers come from the presented stable RGB buffer, not a queued decoder position. Long text ellipsizes visually but retains its full tooltip and native accessibility name.
- Cache unchanged status text so it does not invalidate repeatedly on idle. Zoom/frame text updates do not rebuild the command row or resize the content splitter. Full screen hides both rows. MFC reserves status height exactly once; the DPI-scaled empty startup retains its existing 800x600-class viewing area. Native high-contrast/non-DWM menu fallback remains OS-managed and can wrap.
