## Playable RAW/Y4M controls and actual latest preview — 2026-10-19

The user's running Viewer was still Issue120RawPlaybackReview, predating the already committed Options additions in 609649a; the new menu was not missing from the source/build. The reported .yuv contains a YUV4MPEG2 header and had been opened by VidCapFrmSrc as intrinsically fixed decoded BGR, so merely enabling the existing buttons would have fed mismatched dimensions/format into that decoder. Implement an indexed native-RAW path for supported Y4M layouts instead, selected by signature before the normal image/video/raw order. Other inputs retain their existing order and unsupported Y4M layouts retain decoded-video fallback. Qt and Comparator production code are unchanged.

The Viewer-only bounded reader parses width/height, rational FPS and supported native color space, then indexes actual FRAME payload offsets, allowing variable-length marker tags. It never decodes all frames during discovery. Source reads and per-worker snapshots use those immutable payload boundaries; current resolution/color-space settings can change without reading subsequent marker bytes or the next frame. Missing bytes in larger interpretations are zero-filled; frame count remains the container count. This is different from headerless RAW, whose frame count depends on interpreted frame size. Existing queue/worker lifecycle, explicit autoplay, seek, RAW menu command routing and file reload machinery are reused. Headerless RAW behavior and decoded MP4/JPEG restrictions are preserved. Supported native layouts: 8-bit planar 420 variants/default, planar 420p10 and mono. Other layouts fall back to the existing video reader. Format reference reviewed: [FFmpeg Y4M demuxer](https://raw.githubusercontent.com/FFmpeg/FFmpeg/master/libavformat/yuv4mpegdec.c); no FFmpeg implementation code is copied into this reader.

Generated coverage checks native payload bytes, variable marker lengths, rational timing, seeking, actual format/resolution commands during playback, safe oversized padding, restored interpretation and autoplay, plus malformed dimensions/unsupported layouts/truncation/overflow-sized headers.
