# Issue #139: reference comparisons

Date: 2026-10-12. Branch: `codex/issue-139-reference-comparisons`. The Windows MFC Comparator changes build on the unmerged #118 appearance branch (`71b5b19`), whose base is master `cf0c29e`. The reference-comparison feature leaves Viewer and Qt behavior unchanged; the Windows painting follow-ups below also harden Viewer backgrounds. No version increase, merge, release tag, Store submission or issue closure is part of this implementation.

## Implemented behavior

- Fixed reference A, stable candidate slots B/C/D, and one independent current-result footer and sequence graph per loaded candidate. A has a non-interactive Reference/frame label; B/C/D results follow the actual bounds of their own image pane, including unequal column widths. Closing B leaves its footer empty while A/C and A/D remain under C/D; closing A clears comparisons without promoting another source and shows a missing-reference instruction in the candidate footers. Source headers identify filenames; compact result names identify pairs and actual frames without repeating filenames. Full-path tooltips retain source resolutions, comparison basis, and channel-level results. RGB aggregate is a tooltip explanation, not a default result annotation. Clicking a result or its graph changes the inspected pair for A's overlay and Timeline detail, not which pairs are calculated.
- Existing native YUV scores and packed-RGB aggregate semantics are retained. RGB aggregate and R/G/B channel values are labelled separately. Both existing LPIPS backends and the existing ROI policy apply independently to every pair. Current results use actual displayed frame indices, including independent seeks, and are computed on owned snapshots in the background. Only each pair's latest request can publish; numerical inference errors are not reported as zero-distance successes. Mismatched displayed indices explicitly show `Unaligned: frame indices differ` without hiding the actual-frame score. C-only seeking/reloading preserves completed A/B and A/D current scores, channel details, ROI results, and request IDs as well as their sequence caches.
- Timeline spans the longest loaded source, with a shared index gutter and up to four sticky source headers. Pair domains are independently `min(A, candidate)`. Missing frames cannot be selected or synthesized by clamping. A global seek updates only sources that have that frame; cards identify actual displayed frames and flag an unavailable aligned frame. Different FPS is disclosed rather than resampled.
- Sequence graphs have separate computed counts, averages and states, a shared frame-index viewport and shared finite Y range. Uncomputed/out-of-domain samples are gaps; infinity is labelled explicitly. Channel line styles and legends distinguish channels without relying solely on color. Plot wheel zoom does not seek; double-click resets the range. A replacement resets the viewport; C-only replacement preserves it. Collapse retains all numerical caches.
- A single coordinated eager scanner decodes/converts A once per aligned frame and scans only eligible candidate frames. Unchanged pair caches and source readers survive candidate replacement. LPIPS uses one serial model session and one worker for the selected backend, not one model/worker per candidate. Current measurements use at most one active pair and three independently replaceable pending pair slots; affected pairs share their batch's owned source snapshots, with A copied once per batch. Round-robin dispatch prevents repeated C requests from starving B/D and supersession rejects only that pair's obsolete result. There is no unbounded work queue. Sequence caches still grow with frame count and RLC complexity, as before, now for up to three pairs; this is not a claim of constant memory usage or universal throughput improvement.
- Current results stay aligned with their source columns in narrow windows; measured footer heights retain wrapped ROI/warning text using the same themed native vertical scrollbar as #118 instead of shrinking fonts or moving a result to another source column. Separate sequence graphs still stack when narrow. The default current-result strip is 72 DIP, reduced from 120 DIP after moving repeated filenames and channel details into tooltips. Tab/Enter select available result footers, and focus can leave the result strip. The graph panel collapses independently of its caches. Image canvas height remains usable in the tested 800×500 window. Stills show compact single-frame messages, not artificial time curves.

This supersedes the earlier A/B-only / C-and-D-view-only assumption in the #129–#131 design tasks. A selectable arbitrary reference, pairwise combinations, timestamp resampling, the #116 2×2 source layout, and a redesign of native menus are not included. No user-owned files in the untracked `docs/design/desktop-redesign-2026-10-03/` directory were changed.

## Pair-specific current refresh and unaligned-frame follow-up (2026-10-13)

Re-review of #139 found that current results still used a global frame/signature/request ID, although sequence caches already had pair-specific generations. The new regression first failed on the original behavior: seeking only C reset completed A/B and A/D results to Computing (`Tests/bin/x64/Release/comparer-pair-refresh-before.txt`). Independent displayed indices also lacked the required explicit Unaligned notice.

Current-result keys now include only the pair's source generation and actual A/candidate frames plus shared canvas dimensions, selected metric/model availability, and committed ROI. Only changed pairs copy source snapshots and receive a new request ID; completed unchanged pairs retain all score/channel/ROI fields through candidate reload and closing another candidate. A, metric, or shared ROI changes still refresh every affected pair. Interrupted/error requests are resubmitted when analysis restarts rather than leaving cancelled work stuck in Computing.

The coordinator now has three replaceable pending pair slots and processes one current pair at a time, round-robin, interleaved with the eager sequence scan. Each pair independently checks its latest request before measuring and before publication. A newer C request cannot cancel an in-flight B result; a superseded C result cannot overwrite its replacement. A single request for several changed pairs shares its owned snapshots, copying A once. The worker exposes locked current-measurement counts and pending masks for diagnostic/regression checks; those counts are current jobs, not a direct LPIPS inference-call counter.

The final real-MFC report, `Tests/bin/x64/Release/comparer-pair-refresh-after.txt`, has 690 PASS checks, exit 0, no FAIL/ERROR. The 31 added checks cover PSNR/SSIM C-only seek, preserved B/D result fields/request IDs/measurement counts, C-only reload and unchanged sequence decodes, closing B, explicit warning appearance/removal, back-to-back C/D seeks, global A/ROI invalidation, and real AlexNet/VGG LPIPS current/ROI results against direct inference on the actual mismatched frames. Deterministic callbacks queue replacements during real metric calculations to exercise both cross-pair and same-pair publication races without timing-dependent sleeps or production pause hooks. A burst of 100 C requests occupies one pending slot and measures only the latest snapshot. Cancellation rejects old/zero request IDs.

CoreRegressionTests, WindowsUiTypographyTests, and the ordinary Release/x64/v143 Comparator build pass. The ordinary preview is `Comparator/x64/Issue139PairReview/Comparator.exe`. Seeking only C to 32 changed A/C to 29.7008 dB and visibly added `Unaligned: frame indices differ`; B/D stayed at 33.9524/29.3136 dB, while all three sequence graphs retained their cached data and eligible counts (150/90/150). The warning remains in the native result button's accessible name and wraps/scrolls with existing footer layout. This native check uses 96 DPI and 100% text size, not a newly completed high-DPI acceptance test.
