# Issue #119: Windows command availability and interaction states

Date: 2026-10-18 (Asia/Seoul). Branch: `codex/issue-119-command-states`, based on `origin/master` `65b53d4`. Scope is Windows MFC Viewer and Comparator only. The user initially requested implementation/re-review, then explicitly authorized merge/release and computer shutdown after successful verification. Other redesign jobs and global Windows setting changes remain excluded. Existing untracked design assets are read-only reference material and are excluded from delivery.

## Incremental command audit

| Existing command | Shared applicability | Entry points retained |
| --- | --- | --- |
| Viewer resolution/color-space dynamic IDs, N/D helpers | Empty-session RAW setup or a non-fixed RAW source; never reinterpret a decoded image/video | Native/hosted menus, MFC command dispatch, direct handlers and existing shortcut/sync helpers |
| Viewer Copy | Presented image pixels, not an old buffer during loading | Original Ctrl+C/menu command and handler; no clipboard overwrite in availability checks |
| Viewer Paste | The DIB/DIBV5 formats the existing paste handler actually accepts | Original Ctrl+V/menu command and handler; availability does not open/read/write clipboard data |
| Viewer main Compare | An actual source file path | Original Compare command and handler; the separate browser selection command retains its 2–4-file policy |
| Comparator source format | Empty-slot RAW setup or a source without fixed decoded dimensions | Source-local popup, command routing and direct handler; each popup updates against its own source, not another active view |
| Comparator Clear selection | Existing committed or in-progress selection | Context menu and handler; Esc retains its existing local clear behavior |

`Q1UiCommandWin.h` owns applicability and unavailable-reason definitions, not a new command framework. Viewer menus/handlers/help reuse those definitions; Comparator source and selection controls use the same policies. Native check/radio metadata stays intact. Invalid/unassigned dynamic IDs are rejected before parsing or showing custom-input dialogs. The Viewer's dynamic mouse-menu range also rejects unused indices rather than indexing beyond its command table.

Other audited entries are deliberately retained: File/Open, help, window/system/Alt commands, theme, drawer, autoplay preference, scaling policy, updates and Sync Input retain their current meaning. FPS remains configurable; Comparator's global resolution setting remains its existing comparison-canvas/resizing policy, not the per-source RAW-only rule. Browser batch operations keep their separate selection-specific IDs and validation. No claim is made that every application command has been migrated to the new small policy table.

## Interaction and painting

The source popup is an actual native BUTTON with its original MFC command IDs, accessible name/role/enabled/focus state and WS_TABSTOP. Filenames are native read-only STATIC labels, with literal ampersands and no tab stop. Pointer hover uses leave tracking without taking capture. Native release and Space activation queue one popup after native release/capture processing; Enter/Down/F4 reuse that same action and held-key repeats are rejected. Duplicate pending activations coalesce. Tab moves locally between an eligible source canvas and its format button; global key routing, IME and unrelated list/graph keys are unchanged.

Native popup tracking returns the selected ID and dispatches it once. It retains initialization notifications for owner/source state and shared menu typography; it must not use TPM_NONOTIFY. Windows handle/permanent-object checks avoid accessing a destroyed control after a modal popup returns. Reflected native owner-draw and local paint share a complete buffered painter, including state invalidation, restored GDI objects and focus indication. Menu buttons and popups use measured text/DPI hit areas with a 32-DIP minimum menu row; source-format buttons use a compact 28-DIP minimum plus text/chevron/padding measurement. Disabled commands do not receive hover/pressed emphasis; custom disabled boundaries use a dashed pattern and keyboard focus uses an inset outline, not color alone. Read-only zoom status is not decorated as an unavailable action.

Availability changes update existing native controls rather than recreating menus, resizing image panes or restarting decoders/metrics. Native fallback menu redraw happens only on changed top-level availability. Context help is rerendered only when relevant availability changes. No new animation, periodic decoration timer, source-pixel/color-conversion change or comparison algorithm is introduced. Approved Q1 icons and typography/theme choices are retained; Qt files are untouched.

## Design and implementation re-review

Retain the incremental shared applicability/reason policy and existing MFC execution handlers rather than introducing a second dispatcher. Check each selected command at its original handler and alternate helpers as well as at command routing. Do not impose the Viewer's RAW resolution restriction on Comparator's comparison-canvas resize policy. This remains a bounded command audit, not an assertion that every application command has been migrated.

The re-review found and corrected four further inconsistencies: Viewer help availability was skipped when full screen hid the menu; native fallback redraw omitted changes to the top-level Compare command; right alignment incorrectly classified disabled Compare as read-only zoom status; and source-label measurement could replace the established DPI-aware header height. Read-only status now has an explicit command role, and label changes preserve header/canvas/close geometry. Light/Dark pixel tests distinguish disabled action boundaries from the undecorated zoom label.

Ordinary-app file opening then exposed a real missing state transition: format labels are prepared before `OpenFrmSrc` commits the new source, leaving decoded-source buttons visually enabled even though execution guards rejected them. The earlier integration test masked this by explicitly calling `RefreshCommandStates`. The test-forced refresh was removed and the failure reproduced in `issue-119-comparer-stale-state-red.txt` (exit 1). Availability now follows the completed MFC `OnUpdate` document notification; unchanged eligibility performs no native state/menu updates during playback or metric notifications. Regression checks cover empty slots, decoded input, changing to RAW and closing a source without a test-forced refresh.
