# Issue #117: approved Windows title/menu frame extension

Date: 2026-10-04. Branch: `codex/issue-117-typography`. Windows MFC Viewer and Comparator only. The user approved expanding beyond a font-only edit after two non-client painting prototypes proved unsuitable. No master merge, release tag, version bump or operating-system font/settings change is authorized by this work.

## Design and implementation

The main title is client-painted using the same normal-weight 14 DIP Pretendard body role as the main menu. A buffered 32-bit title surface explicitly supplies opaque alpha for the title, while leaving the DWM caption-button area transparent. This avoids invisible GDI glyphs on an extended frame and preserves the system-rendered window buttons. The actual window title remains unchanged for Windows accessibility, task switching and taskbar use; long titles use end ellipsis and literal ampersands are not interpreted as mnemonics.

The main menu row uses real accessible Win32 buttons and retains the original HMENU tree for native popup tracking, state updates, shortcuts and owner-drawn popup metadata. Normal text enlargement is not clamped to the former native bar height. Narrow windows wrap menu buttons rather than overlapping the right-aligned Help/Compare/Update/zoom group. Alt mnemonics, Alt/F10 focus, arrow switching, Enter/Down, and Esc focus restoration are handled explicitly. A thread-local, temporary MSGF_MENU filter switches sibling main-menu popups without replacing nested-submenu navigation; it is unhooked before deferred owner-window closure.

Native DWM button handling is given first refusal, with the same non-client button hit codes supplied when DWM hit state is not ready after a frame change. Resize borders, title dragging, title double-click and the Windows system menu continue through the native non-client path. Maximized client bounds account for the invisible resize border and monitor work area. Custom-frame moves/sizes set SWP_NOCOPYBITS rather than assuming standard-client-origin pixel preservation; the flag is regression-tested, but it has not conclusively fixed the mouse-capture observation below. No snap-layout UI is implemented by the app; the maximize button retains HTMAXBUTTON for Windows handling.

MFC reserves the title/menu region via its existing m_rectBorder layout mechanism, so it does not resize the image to full client size and then resize it again below the title. Help and drawer-transition overlays cover the content region rather than intercepting window controls. Comparator splitter heights use the content height. Viewer full-screen transitions hide the chrome and restore the same menu instead of loading another root and reinserting dynamic submenus.

High contrast or unavailable DWM composition restores the native frame/menu. This is a deliberate native-title typography exception. The detached root menu has an explicit lifetime; WM_DESTROY releases it if no HWND owns it. Frame overrides do not access members after MFC's WM_NCDESTROY/PostNcDestroy path deletes the frame.

The architecture follows Microsoft's [custom DWM frame guidance](https://learn.microsoft.com/en-us/windows/win32/dwm/customframe) and keeps [TrackPopupMenuEx](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-trackpopupmenuex) for popup tracking. This is not the rejected approach of painting on top of the system title or disabling DWM non-client rendering.

## Verification

Follow-up to the user's screenshot: Comparator pane format selection and right-click menus were standalone popups, outside the main frame HMENU tree, and still used Windows default popup typography. Each pane now owns a shared WindowsUiMenus painter for its standalone popups and routes native initialization/measurement/drawing/mnemonic messages through it. Color-space command parsing reads the preserved menu label rather than relying on GetMenuString for an owner-drawn item. Standalone popup tests cover row measurement, accessible names, check-state preservation and modified labels. The remaining frame/mouse-capture acceptance caveat below is unchanged.

The typography executable now also creates an isolated Win32 frame and checks original menu retention, accessible button names, disabled-item input, dynamic labels, wrapped/non-overlapping rows at window widths 200/320/640/1920, full-screen hide/restore, native maximize hit codes and repeated buffered caption drawing without accumulating GDI objects. Body/help tests continue to cover explicit 96/120/144/192 DPI and text factors 1/1.25/1.5/2/2.25. These explicit font/layout inputs are not a substitute for a real mixed-monitor or live Windows text-size acceptance run.

The MFC gallery suite adds real chrome-reserved splitter bounds, maximize/work-area bounds, original restore rectangle, three full-screen round trips without duplicate menus and preservation of the active file. It then runs the existing E transition, zoom/pan, playback, selection, directory refresh, recycling and actual GPU recreation tests with an isolated profile and repository/temp fixtures.

Native visual inspection has confirmed 14 DIP title/menu balance in both applications, retained DWM window buttons and rounded frame, actual maximize/restore button clicks, title dragging with unchanged window dimensions, Alt+Space system menu, Alt+F popup access, Right switching to the next main-menu popup and F10/Esc focus restoration.
